# Local Bridge Protocol v1

## Назначение

Протокол связывает обычный разговор ChatGPT с локальным исполнителем внутри Windows-клиента.

Транспорт сейчас использует обычные сообщения разговора ChatGPT. Это не системный и не скрытый канал.

## Начальная инструкция

При включении Local Bridge клиент формирует полную инструкцию и отправляет её через обычное поле ввода ChatGPT как пользовательское сообщение.

Инструкция содержит:

- текущий `session`;
- формат машинного запроса;
- перечень зарегистрированных операций;
- правила использования моста;
- требование подтверждения готовности.

Если мост уже активен, повторное нажатие кнопки **«Мост»** повторно отправляет полную актуальную инструкцию для того же сеанса. Новый сеанс при этом не создаётся.

Технический обмен по текущему решению продукта может быть видим пользователю. Клиент не обязан скрывать `LOCAL_BRIDGE_REQUEST_V1` до того, как пользователь увидит реакцию модели.

## Запрос

Когда модели требуется локальная операция, она формирует один машинный запрос:

```text
[[LOCAL_BRIDGE_REQUEST_V1]]
{
  "session": "<current-session-id>",
  "id": "req-0001",
  "tool": "fs.list",
  "args": {
    "path": "C:/Temp"
  }
}
[[/LOCAL_BRIDGE_REQUEST_V1]]
```

Запрос считается допустимым только при выполнении проверок протокола, включая:

- сообщение сформировано моделью;
- присутствуют начало и конец конверта;
- JSON разбирается полностью;
- `session` совпадает с текущим сеансом;
- `id` корректен;
- операция зарегистрирована;
- разрешения допускают требуемую возможность;
- постоянный журнал не указывает на конфликтующее или уже исполненное действие.

За один ответ модели обрабатывается один машинный запрос.

## Результат

После локального выполнения клиент формирует:

```text
[[LOCAL_BRIDGE_RESULT_V1]]
{
  "session": "<current-session-id>",
  "request_id": "req-0001",
  "ok": true,
  "result": {}
}
[[/LOCAL_BRIDGE_RESULT_V1]]
```

Результат возвращается в тот же разговор как служебное пользовательское сообщение. После этого модель продолжает обычный ответ на языке пользователя.

Модель не должна самостоятельно придумывать `LOCAL_BRIDGE_RESULT_V1`.

## local.intent

`local.intent` — основной вход для обычного пользовательского задания на естественном языке.

Аргумент:

```json
{
  "instruction": "текст команды пользователя"
}
```

Текущая реализация:

1. получает естественную инструкцию;
2. через авторизованный контекст WebView2 получает серверную сессию;
3. временно выбирает подходящую приостановленную задачу ChatGPT;
4. сохраняет её исходное состояние;
5. записывает инструкцию планировщика;
6. выдерживает не менее 5 секунд между завершившимися сетевыми запросами;
7. запускает задачу штатным `POST /backend-api/automation/{id}/run`;
8. получает результат через `latest_backing_run`;
9. проверяет идентификаторы запроса/сообщения и разрешённую операцию;
10. передаёт структурированное действие локальному исполнителю;
11. в `finally` восстанавливает исходную пользовательскую задачу.

Это доказанная рабочая схема, но временная архитектура. Следующая версия должна использовать отдельную постоянную служебную задачу Local Bridge и не касаться пользовательских задач.

## Пауза между сетевыми запросами

Для серверного планировщика действует обязательное правило:

**после завершения одного сетевого запроса до начала следующего должно пройти не менее 5 секунд.**

Параллельные серии сетевых запросов, частый опрос и интервалы менее 5 секунд не допускаются.

Пауза перед единственным запросом не требуется.

Если исход изменяющего сетевого действия неизвестен, слепой повтор запрещён. Сначала выдерживается интервал, затем выполняется авторитетное чтение состояния.

## Прямые локальные операции

Помимо `local.intent`, основная модель получает актуальный перечень зарегистрированных операций непосредственно в начальной инструкции. Среди них файловые операции, `process.run`, `repo.*` и `mcp.*`.

`process.run`:

- 120 секунд — значение времени ожидания по умолчанию;
- положительное `timeout_ms` задаёт требуемое время ожидания;
- `timeout_ms: 0` означает работу без жёсткого верхнего предела времени.

Серверный планировщик `local.intent` пока не имеет всего набора прямых операций основной модели.

## Постоянный журнал

`DurableRequestLedger` разделяет:

- принятие запроса;
- состояние локального выполнения;
- сохранённый результат;
- состояние доставки результата модели.

При неизвестном результате изменяющего действия автоматическое повторное выполнение запрещено.

Следующий архитектурный этап расширит этот журнал от отдельного запроса до многошагового локального задания.

## Разрешения

Файл политики:

`%APPDATA%\ChatGptDesktopLocalBridge\permissions.json`

Режимы:

- `AUTO` — выполнить автоматически;
- `ASK` — запросить подтверждение;
- `DENY` — запретить.

Полномочия пользователя не отменяют защиту самого транспорта.

## Неизменяемые проверки целостности

Даже при полном доверии должны сохраняться:

- идентификатор сеанса;
- уникальность и связь номера запроса;
- проверка структуры;
- проверка зарегистрированной операции;
- защита от повторного исполнения;
- защита от повторной доставки;
- журналирование;
- ограничение размеров входных и выходных данных там, где оно установлено;
- правило неизвестного исхода для изменяющих действий.
