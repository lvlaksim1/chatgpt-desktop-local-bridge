# ChatGPT Desktop Local Bridge

Windows-клиент ChatGPT с WebView2 и встроенным Local Bridge для работы с локальным компьютером через обычный `chatgpt.com` и пользовательскую подписку ChatGPT, без OpenAI API.

## Продуктовая основа

Единственная продуктовая ветвь — `main`.

Актуальная продуктовая линия была консолидирована в `main` 07.10.2026. Экспериментальные ветви не являются источником актуального продукта.

Текущий проверенный объединяющий коммит:

`d24c58b9c7304cd6e187e937262fdded1afbf85a`

Он объединяет выпущенную линию Local Bridge с политикой хранения репозитория из прежнего `main`.

## Как работает мост

Основной цикл:

```text
обычная команда пользователя
  -> модель определяет, требуется ли локальное действие
  -> LOCAL_BRIDGE_REQUEST_V1
  -> встроенный C# Local Bridge
  -> проверка сеанса, запроса и разрешений
  -> локальная операция Windows
  -> LOCAL_BRIDGE_RESULT_V1
  -> продолжение того же разговора ChatGPT
```

Для обычных команд на естественном языке основным входом является `local.intent`. Он передаёт пользовательскую формулировку серверному планировщику ChatGPT, получает структурированное локальное действие из разрешённого набора и передаёт его штатному исполнителю Local Bridge.

Текущий архитектурный долг: `local.intent` пока временно заимствует подходящую приостановленную задачу ChatGPT, сохраняет её исходное состояние, использует для одного запуска и затем восстанавливает. Следующий продуктовый этап — собственная постоянная служебная задача Local Bridge, не зависящая от пользовательских задач.

## Доступные локальные операции

В текущем продукте зарегистрированы:

- `system.info`;
- `fs.list`;
- `fs.read_text`;
- `fs.write_text`;
- `fs.append_text`;
- `fs.write_file`;
- `fs.copy_first_line`;
- `process.run`;
- `repo.status`;
- `repo.diff`;
- `repo.map`;
- `repo.checkpoint`;
- `repo.verify`;
- `mcp.list_servers`;
- `mcp.list_tools`;
- `mcp.call`;
- `local.intent`.

Серверный планировщик `local.intent` пока использует более узкий набор структурированных файловых действий. Более широкие операции, включая `process.run`, доступны основной модели непосредственно через Local Bridge.

### Длительность process.run

Если `timeout_ms` не указан, используется 120 секунд.

`timeout_ms: 0` означает отсутствие жёсткого верхнего предела времени выполнения. Процесс продолжается до собственного завершения, отмены мостом или остановки пользователем.

## Инициализация и кнопка «Мост»

При инициализации клиент автоматически передаёт модели полную инструкцию Local Bridge:

- идентификатор текущего сеанса;
- формат `LOCAL_BRIDGE_REQUEST_V1`;
- актуальный список зарегистрированных операций;
- правила обмена.

Если мост уже активен, повторное нажатие кнопки **«Мост»** не создаёт новый сеанс. Клиент повторно передаёт модели полную актуальную инструкцию для существующего сеанса. Это позволяет восстановить контекст моста в очень длинном разговоре.

Технические сообщения протокола намеренно не маскируются полностью: пользователь может видеть реакцию модели и сформированный запрос моста.

## Серверное планирование local.intent

Текущий цикл:

```text
модель в обычном чате
  -> local.intent
  -> сохранить инструкцию во временно используемой приостановленной задаче
  -> пауза не менее 5 секунд после завершения сетевого запроса
  -> штатный немедленный запуск /automation/{id}/run
  -> пауза не менее 5 секунд между сетевыми запросами
  -> latest_backing_run
  -> проверка связи запроса и ответа
  -> структурированное локальное действие
  -> Local Bridge
```

Правило проекта: между последовательными внутренними или внешними сетевыми запросами должно быть не менее 5 секунд тишины. Перед одиночным запросом искусственная задержка не требуется.

## Разрешения и целостность

Политика разрешений хранится вне кода:

`%APPDATA%\ChatGptDesktopLocalBridge\permissions.json`

Используются режимы `AUTO / ASK / DENY`.

Независимо от уровня доверия сохраняются проверки целостности транспорта:

- идентификатор сеанса;
- уникальный номер запроса;
- защита от повторного выполнения;
- проверка структуры запроса;
- проверка зарегистрированной операции;
- постоянный журнал запросов;
- разделение выполнения действия и доставки результата;
- защита от повторной доставки уже выполненного результата.

## Интерфейс

Клиент использует WPF/.NET 8 и WebView2. В приложении есть:

- вкладки разговоров;
- правая панель активности Local Bridge;
- консоль;
- кнопка STOP;
- настройки темы;
- установленная версия приложения в интерфейсе;
- обновление через отдельный установщик обновления.

Исследовательские элементы ещё присутствуют в кодовой базе и должны быть отделены от обычного пользовательского интерфейса на последующем этапе.

## Установка и обновление

Программа устанавливается для текущего пользователя в:

`%LOCALAPPDATA%\Programs\ChatGPT Desktop Local Bridge`

Постоянный профиль WebView2 расположен отдельно:

`%LOCALAPPDATA%\ChatGptDesktopLocalBridge\WebView2`

Поэтому обычное обновление программы не должно удалять авторизацию ChatGPT и состояние браузерного профиля.

Для следующих выпусков предпочтителен небольшой одиночный установщик обновления вида:

`ChatGptDesktopLocalBridge-Update-from-<базовая-версия>.exe`

Полный Setup остаётся для первой установки и восстановления.

При удалении приложение спрашивает:

**«Удалить также настройки и рабочие данные?»**

При отказе пользовательские данные и профиль WebView2 сохраняются.

## Хранение репозитория

В `main` действует политика ненакопления тяжёлых файлов:

- исполняемые файлы, библиотеки, архивы и отладочные файлы не должны попадать в историю Git;
- отслеживаемый файл больше 5 МБ считается нарушением;
- тяжёлые распространяемые файлы хранятся в актуальном GitHub Release;
- процесс очистки сохраняет только последний выпуск и удаляет завершённые временные артефакты GitHub Actions.

## Ближайшее развитие

1. Создать собственную постоянную служебную задачу для `local.intent`.
2. Убрать зависимость от любых пользовательских приостановленных задач.
3. После этого ввести многошаговое локальное задание и расширить постоянный журнал с запроса до задания и его шагов.
4. Затем расширять структурированные локальные возможности, длительные процессы, разрешения и правую панель выполнения.
5. Проверки сложных отказов и длительной устойчивости проводить после формирования нормального рабочего пользовательского пути.
