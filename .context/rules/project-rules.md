# Project rules

1. Product truth is `main`; durable manager truth is `manager-state`.
2. Reconcile live `main`, CI, and release evidence before consequential product work or completion claims.
3. Persist significant BDI/current/handoff changes as one sealed manager generation.
4. Do not store credentials, cookies, private tokens, hidden reasoning, or WebView profile contents in Git.
5. Maintain ordinary development autonomy, but keep stable release, mandate changes, destructive history operations, and material product-direction changes Owner-gated.
6. Live ChatGPT/WebView behavior requires Owner-side Windows evidence where CI cannot reproduce the signed-in product surface.
7. Preserve user drafts and do not silently overwrite non-empty ChatGPT composer contents when the bridge sends service/result messages.
8. A DOM compatibility failure pauses bridge automation rather than triggering blind retries.
9. A request identity that may cause mutation must eventually be durable across restart; RAM-only dedupe is not sufficient for destructive capabilities.
10. Shell/process execution requires a reliable emergency STOP that terminates the owned process tree.
11. External projects are references, not authority. Reuse code only under an explicit compatible license.
12. Use GitHub connector/repository-native workflows for repository work; do not use TinyFish.
