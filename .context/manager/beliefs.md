# Убеждения менеджера

Поколение: 35.
Обновлено: 2026-10-07 17:50 MSK.

- Единственная продуктовая ветвь проекта — `main`.
- 07.10.2026 продуктовая линия Local Bridge консолидирована в `main`: выпущенная линия `0818d61` объединена с прежней историей `main` и актуальной политикой хранения репозитория.
- Объединяющий продуктовый коммит `d24c58b9c7304cd6e187e937262fdded1afbf85a` успешно прошёл штатную сборку Windows, создание полного установщика, пробную сборку обновления, E2E-обновление со старой версии и проверку сохранения пользовательских данных при удалении.
- После консолидации README и описание протокола актуализированы в `main`; текущий head документации — `9431ef3045385accd6df3d84a00da0b0dc3654d7`.
- Актуальный опубликованный выпуск остаётся `local-bridge-runnow-0818d61`, target `0818d61eb48a4cb57304d83f922c8a32a989b2a3`.
- `local.intent` уже является частью установленного Local Bridge. Пользовательский путь «обычная команда в чате -> серверное планирование -> структурированное локальное действие -> выполнение на ПК -> результат модели» подтверждён.
- Основная модель получает начальную инструкцию Local Bridge как обычное пользовательское сообщение текущего разговора и сама решает по смыслу запроса, нужен ли компьютер.
- Повторное нажатие кнопки «Мост» при активном мосте повторно передаёт полную актуальную инструкцию для существующего сеанса и не создаёт новый сеанс.
- По решению владельца технический ответ модели с `LOCAL_BRIDGE_REQUEST_V1` не требуется предварительно скрывать: владелец хочет видеть реакцию модели и сформированную локальную команду.
- `process.run` имеет 120 секунд по умолчанию. `timeout_ms=0` означает отсутствие жёсткого верхнего предела времени выполнения.
- Правило владельца: не менее 5 секунд тишины между последовательными сетевыми запросами; перед единственным запросом искусственная задержка не нужна. Параллельные серии сетевых запросов и частый опрос запрещены.
- Рабочий серверный путь использует штатный немедленный запуск `/automation/{automation_id}/run` и получение результата через `latest_backing_run`; короткое расписание и Library не нужны.
- Главный текущий архитектурный долг: `local.intent` временно заимствует подходящую приостановленную пользовательскую задачу, изменяет её, запускает и восстанавливает. Это допустимо как доказательство, но не как постоянная архитектура.
- Следующий обязательный этап — собственная постоянная служебная задача/сущность Local Bridge, независимая от наличия пользовательских задач.
- После этого приоритет — многошаговое локальное задание над существующими зарегистрированными операциями и расширение постоянного журнала от одного запроса до задания и его шагов.
- Сначала строится нормальная рабочая система. Расширенные испытания дублей, старых ответов, обрывов и длительной устойчивости проводятся после основного пользовательского пути.
